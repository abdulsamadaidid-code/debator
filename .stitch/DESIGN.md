# Debator Design System

Debator is a debate-first social product. It should feel like a deliberate arena for ideas, not a chaotic social feed. The UI should communicate structure, consent, and intellectual energy.

## Brand Direction

- Product mood: editorial, high-signal, modern social, thoughtful, slightly competitive
- Personality: rigorous, welcoming, intelligent, energetic, not sterile
- Avoid: generic startup SaaS, purple gradients, gamer UI, noisy social-media clutter

## Core Visual Language

- Backgrounds: warm parchment and stone tones with soft atmospheric gradients
- Surfaces: creamy cards with subtle borders and low, soft elevation
- Primary accent: deep teal for trust, structure, and primary actions
- Secondary accent: clay orange for energy and conflict
- Support accent: muted navy for data, evidence, and secondary emphasis
- Corners: rounded and soft, but not bubble-like
- Shadows: diffused, editorial, low-contrast shadows rather than sharp material depth

## Typography

- Display/headline font: `Space Grotesk`
- Body/interface font: `Plus Jakarta Sans`
- Headlines: strong, compact, slightly editorial
- Body text: highly readable, neutral, dense enough for argument-heavy content
- Debate proposition text should always be visually dominant over metadata

## Component Rules

### Navigation
- Mobile bottom navigation should feel docked, safe-area aware, and intentional
- Desktop navigation should feel like a workspace rail, not a consumer sidebar
- Active states should be clear without becoming loud

### Cards
- Debate cards: proposition first, then title/context, then metrics
- Topic cards: identity-driven, each should feel like an arena with its own mood
- Profile/status cards: calmer and more factual than feed cards

### Buttons
- Primary actions use teal fills
- Secondary actions use bordered or tinted surfaces
- Destructive actions should be rare and clearly separated

### Badges and Pills
- Use restrained pills for format, live status, topic, reputation, and environment
- Badges should not overpower proposition text

### Forms
- Clean sectioning with concise guidance
- Inputs should feel editorial and premium, not enterprise-heavy
- Important context should appear in small informative banners above or below fields

## Layout Rules

- Mobile-first with intentional tablet and desktop compositions
- Wide layouts should not just stretch cards; they should rebalance into columns
- Debate detail should feel like a reading interface plus side intelligence
- Create and onboarding should feel more guided and focused than feed screens

## Product-Specific Design Principles

1. The proposition is the hero.
2. Every screen should help the user decide, join, argue, follow, or return.
3. Debate needs structure signals everywhere: side labels, round labels, judging framing, reputation, norms.
4. Tension is good, chaos is bad.
5. The app should feel high-signal enough for serious debaters but approachable enough for curious readers.
